First injection

From RTL to a visible bit flip

Instrument an eight-bit counter, compile its generated injection API, and flip one bit while the simulation runs.

The example starts with a normal counter value of 1. At the next clock edge it would become 2. vRTLmod flips bit 0 of the updated state, so the harness observes 3 and checks that result.

1. Choose matching tools

You need a C++ compiler, CMake, Verilator, and LLVM with Clang development libraries. Use the same Verilator installation to build vRTLmod and generate your model. The commands below use Linux, Bash, C++17, and LLVM 18. The complete counter example was checked with Verilator 5.020 and 5.054 using GCC 13.

On a Debian or Ubuntu release whose configured repositories provide LLVM 18, the dependency packages are:

sudo apt update
sudo apt install build-essential cmake git verilator \
  llvm-18-dev libclang-18-dev clang-18 libzstd-dev

Package availability varies by distribution. vRTLmod supports LLVM/Clang 13–18; if you install another supported version, adjust LLVM_DIR and the Clang path below together. Verilator 5.054's CMake package requires CMake 3.19 or newer.

SystemC is optional here. This example generates a plain C++ model. SystemC is needed for SystemC models and the corresponding integration tests. C++17 and newer vRTLmod builds do not require Boost.

This walkthrough selects Verilator from PATH. In the shell used for the example, clear any overrides that would select a different installation:

unset VERILATOR_ROOT VERILATOR_BIN
verilator --version

For a custom installation, put its bin directory first on PATH before continuing. See toolchain selection for explicit CMake roots.

2. Build and install vRTLmod

git clone --recurse-submodules https://github.com/tum-ei-eda/vrtlmod.git
cd vrtlmod
cmake -S . -B build \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CXX_STANDARD=17 \
  -DLLVM_DIR=/usr/lib/llvm-18/lib/cmake/llvm \
  -DCMAKE_INSTALL_PREFIX="$PWD/install" \
  -DBUILD_TESTING=OFF
cmake --build build --parallel 2
cmake --install build
export PATH="$PWD/install/bin:$PATH"

The configure output reports the selected Verilator executable, runtime root, and version. Check that these match the installation you intend to use. Set the install prefix during configuration, as shown above.

3. Get the counter and harness

From the repository directory, copy the two example files into a separate working directory:

mkdir -p counter-demo
cp docs/site/examples/counter.sv docs/site/examples/main.cpp counter-demo/
cd counter-demo

You can also download counter.sv and main.cpp into an empty directory if you already have vRTLmod installed.

The RTL has a synchronous reset and an enable:

module counter (
    input  logic       clk,
    input  logic       reset,
    input  logic       enable,
    output logic [7:0] count
);
    always_ff @(posedge clk) begin
        if (reset)
            count <= 8'd0;
        else if (enable)
            count <= count + 8'd1;
    end
endmodule

4. Generate and instrument the C++ model

verilator --cc --top-module counter --prefix Vcounter \
  --Mdir obj_dir counter.sv

vrtlmod --out=modified obj_dir/Vcounter*.cpp obj_dir/Vcounter*.h \
  -- /usr/lib/llvm-18/bin/clang++ -xc++ -std=c++17 -Iobj_dir

Verilator creates the original model in obj_dir. vRTLmod copies and instruments its code in modified; the original files remain available. Pass both the generated C++ sources and headers. The arguments after -- configure Clang's parsing of those files.

5. Compile and run the simulation

This small, cycle-based model needs Verilator's base runtime and, when provided by the installation, its thread runtime. The Bash array below selects those files without assuming an install-prefix layout:

VERILATOR_SHARE="$(verilator --getenv VERILATOR_ROOT)"
runtime_sources=("$VERILATOR_SHARE/include/verilated.cpp")
if [[ -f "$VERILATOR_SHARE/include/verilated_threads.cpp" ]]; then
  runtime_sources+=("$VERILATOR_SHARE/include/verilated_threads.cpp")
fi

c++ -std=c++17 -O1 \
  -Imodified \
  -I"$VERILATOR_SHARE/include" \
  -I"$VERILATOR_SHARE/include/vltstd" \
  main.cpp modified/Vcounter*.cpp "${runtime_sources[@]}" \
  -pthread -o counter-demo
./counter-demo

Both tested Verilator versions, 5.020 and 5.054, produce:

TOP.count: 8 bits, injectable=1
Injected bit 0 of TOP.count: count=3 (expected 3)

The harness returns a nonzero exit code if initialization, target selection, preparation, or the observed fault is wrong. Target names may change with Verilator versions and optimization; the harness selects the sole injectable eight-bit entry instead of hardcoding its name.

For larger builds, use CMake's model metadata. Models using tracing, coverage, timing, or other features can require additional runtime sources and libraries. The CMake integration guide shows where the maintained example obtains the runtime selected by Verilator.

6. Understand the injection sequence

The downloaded harness owns a VcounterVRTLmodAPI. Its vrtl_ member is the normal Verilator model; its td_ dictionary lists generated targets. After reset and one ordinary count, the harness finds the counter, prepares bit 0, and arms it:

// Inside the example harness; target is selected from simulation.td_.
target->disarm();
target->reset_mask();
if (simulation.prep_inject(*target, 0) != vrtlfi::td::TD_API::GENERIC_OK)
    return 1;
target->arm();
tick();                    // Drive clk low, high, low, evaluating each phase.
target->disarm();

prep_inject() sets the mask and resets injection counters. It does not arm the target. The generated model hooks apply the fault while the relevant state update executes. Calling arm() alone does not advance simulation time or create a clock edge.
