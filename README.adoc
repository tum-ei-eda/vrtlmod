== Brief

The Verilated RTL modifier (vRTLmod) is an LLVM based open-source tool to enable fault injection in verilator RTL (vRTL) simulations.

Within an Clang-Frontend (LLVM) tool it automatically adds fault injection capability to https://www.veripool.org/wiki/verilator[Verilator] output. Additionally, `vRTLmod` can make use of its own XML output `*-vrtlmod.xml` as a whitelist filter argument to allow manual steering of wanted/unwanted injectable variables.

== Setup

=== Native (Debian)

==== Requirements

. vRTLmod dependencies: `build-essential, make, cmake, g++`
  * Verilator v5.054's CMake integration requires CMake >=3.19.
  * C++17 and newer builds do not require Boost.
  * Older C++ standards additionally require Boost.Filesystem >=1.70 (`libboost-filesystem-dev`).
. Verilator (see: https://www.veripool.org/wiki/verilator and install guide).
  * Supports Verilator major versions 4 and 5; the v5 compatibility target is v5.054.
  * Regression-tested with v4.228 and v5.054 using LLVM 18 and SystemC 2.3.4.
  * v5.020 and v5.046 were also integration-tested during development.
  * Build vRTLmod against the same Verilator version used to generate the input model.
. LLVM+Clang versions >=13 and <=18
    * Debian-based distros: `apt install update && apt install llvm-15-dev libclang-15-dev clang-15`
    * From Source: Make sure to build with `LLVM_ENABLE_PROJECTS="clang;clang-tools-extra"`
. For Tests: SystemC>=2.3.3 (set environment variable before CMake, `export SYSTEMC_HOME=/path/to/systemc/`)

==== Build (Debian)

Environment::
[,bash]
----
export LLVM_DIR=<path/to/llvm/install/dir>/lib/cmake/llvm
# Optional: pin a custom Verilator installation instead of using PATH.
# export VERILATOR_ROOT=<path/to/verilator/build/or/install/directory>
export SYSTEMC_HOME=<path/to/systemc/install>
----

Configure project directory (CMake)::
[,bash]
----
cmake -S . -B build [-D VERILATOR_ROOT=<path/to/verilator/build/or/install/directory>] [-D LLVM_DIR=<path/to/llvm/install/dir>] [-D BUILD_TESTING=Off]
----
Build::
[,bash]
----
cmake --build build [--parallel $(nproc)]
----
Install (optional)::
[,bash]
----
cmake --build build --target install
----
Test (optional: configure with `-D BUILD_TESTING=On`)::
[,bash]
----
cmake --build build --target test 
----

Verilator discovery uses `VERILATOR_ROOT` passed to CMake (including a cached value), then the `VERILATOR_ROOT` environment variable, then `verilator` on `PATH`.
Omit both root settings to use a system package. An explicit root accepts a source/build tree, an install prefix, or its `share/verilator` directory; invalid roots fail configuration.
CMake reports the selected executable, runtime root and version, and uses that installation's matching headers and CMake package.
The selected root is cached; use separate build directories when switching installations.
Model generation uses `vrtlmod_verilate(target ...)`, which accepts the arguments of Verilator's `verilate()` function and keeps configure and build commands on the selected installation.
For older Verilator packages without a command hook, this requires a Makefile or Ninja generator. The environment handling uses CMake and adds no launcher script or Perl requirement of its own; Verilator's own Perl requirements still apply.
The tests cover cycle-based C++, SystemC, the downstream CMake helper, and clock/reset scheduling with both split and inlined generated functions.
Timing/coroutines, DPI, and multithreaded models are not covered by these tests.

=== Docker

A `docker compose` flow is provided.

Compose the Docker image `vrtlmodworkspace`... grab a ☕ and wait ... this takes a while.::
[,bash]
----
docker compose -f docker/docker-compose.yaml build vrtlmodworkspace
----
Next, launch the container and mount the workspace::
[,bash]
----
docker run -it -v"$PWD":/vrtlmod docker-vrtlmodworkspace:latest
----

NOTE: `-v"$PWD":/vrtlmod` makes the `vrtlmod` directory available in the container. Mount other directories if necessary.

== Usage

=== Run vRTLmod from Command Line 

Required inputs::
https://www.veripool.org/wiki/verilator[Verilator] output: `<VRTL-files>` `<VRTL-Hpp-files>`

When `VERILATOR_ROOT` is an install prefix, use `${VERILATOR_ROOT}/share/verilator/include` in the command below.

Command::
[,bash]
----
vrtlmod [--systemc] [--wl-regxml=<*-vrtlmod.xml>] --out=<outputdir> <VRTL-Cpp-files> \
         -- clang++ -I <VRTL-Hpp-dir> -I "${LLVM_DIR}/lib/clang/.../include" \
         -I "${VERILATOR_ROOT}/include" [-I<path/to/systemc/include>]
----

The target list follows Verilator's generated clocked regions. Optimization can split arrays into separate targets or merge downstream combinational assignments into those regions.
Review the generated `*-vrtlmod.xml` and use `--wl-regxml` when a fault campaign requires a specific target set; regenerate the whitelist when changing Verilator versions or optimization settings.

Required inputs::
Use installed `vrtlmod/install/path/vrtlmod-config.cmake` in CMake environment. Add 

The output can be found at `<outputdir>/` in form of altered Cpp files (`<vRTL-Cpp-files>`) and the built injection API inside `<outputdir>/` in the form of `<top>_vrtlmodapi.{cpp,hpp}` including the target dictionary and API wrapper.

Command (Example from `test/fiapp`)::
[,bash]
----

      -D SystemCLanguage_DIR=$SYSTEMC_HOME/lib/cmake/SystemCLanguage

cmake --build build-test # invokes vrtlmod automatically once sources are verilated
----
